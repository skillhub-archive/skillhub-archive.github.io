A. Lists: an ordered collection

A list holds several values in order, written in square brackets and separated by commas. Each value is an item (or element), and each item has an index, its position number. The catch that trips up every beginner: indexes start at 0, not 1.

jobs = ["Move", "Pack", "Storage"]   # a list of 3 strings
print(jobs[0])      # the first item, index 0 -> Move
print(jobs[2])      # the third item, index 2 -> Storage
print(jobs[-1])     # negative counts from the end: last item -> Storage
print(len(jobs))    # len() counts the items -> 3

B. Changing a list: slicing & methods

Lists are mutable, meaning you can change them after they're created (unlike a string or number). Assign to an index to replace an item, and use built-in methods (actions you call with a dot) to grow it with .append, reorder it with .sort, and more.

A slice grabs a range of items with list[start:stop]. Just like range from Session 2, the stop is excluded.

nums = [30, 10, 20]
nums.append(40)     # .append adds an item to the end -> [30, 10, 20, 40]
print(nums[1:3])    # a slice: items 1 and 2, stop 3 excluded -> [10, 20]
nums.sort()         # .sort reorders in place, smallest first -> [10, 20, 30, 40]
print(10 in nums)   # the "in" operator tests membership -> True

C. Tuples & sets

Two more containers, each with one defining trait:

  • A tuple is like a list but immutable, it can't be changed after you make it. Written in parentheses. Use it for a fixed group of values that belong together and shouldn't move (a coordinate, a row).
  • A set is an unordered collection of unique items, written in curly braces. It automatically drops duplicates and is great for fast membership tests.
point = (3, 4)          # a tuple: two values that belong together, fixed
print(point[0])         # index it like a list -> 3

tags = {"vip", "new", "vip"}   # a set: the duplicate "vip" collapses
print(tags)             # only unique items; order isn't guaranteed, so yours may print differently -> {'vip', 'new'}
print("vip" in tags)    # fast membership check -> True

The everyday use of a set is de-duping: pass a list you already have to set() and the repeats fall away. set([1, 1, 2]) gives {1, 2}.

D. Dictionaries: labelled data

A dictionary (dict) stores data as key: value pairs. Instead of reaching by position like a list, you reach by a name (the key). This is how you model a record: one thing with several named fields.

Four things you'll do with a dict: look up a field by key (d["name"]); add or change one by assigning to a key (d["city"] = "..."); read one that might be missing safely with .get(key, default), which hands back your default instead of crashing; and test whether a key exists with in. Here they are together:

customer = {"name": "Ada", "city": "Denver", "vip": True}   # a record, 3 fields
print(customer["name"])          # look up a value by its key -> Ada
customer["city"] = "Boulder"     # change an existing field
customer["phone"] = "555-0100"   # a new key adds a new field
print(customer.get("email", "none"))  # .get returns a default if the key is missing -> none
print("vip" in customer)         # "in" on a dict checks KEYS, not values -> True

Two gotchas worth burning in: reaching a missing key with customer["email"] is an error, use .get() when a field might be absent. And in looks at the keys, so "Ada" in customer is False even though it's a value.

E. Iterating & list comprehensions

You already loop over a range (Session 2). You can loop over any container the same way, for item in list. To build a new list from an old one, there's a clunky way and a clean way. Here's the contrast:

# The clunky way: start with an empty list, loop, and append each result
prices = [10, 20, 30]
with_tax = []
for p in prices:
    with_tax.append(p * 1.1)   # add each taxed price
print(with_tax)                # [11.0, 22.0, 33.0]

# The clean way: a LIST COMPREHENSION does the same in one line
with_tax = [p * 1.1 for p in prices]   # reads: "p*1.1 for each p in prices"
print(with_tax)                        # [11.0, 22.0, 33.0]

▶ watch the comprehension run step-by-step in Python Tutor

Once it clicks, the comprehension is the everyday tool: less code, and no empty-list-then-append ceremony. You can even add a filter: [n for n in nums if n > 0] keeps only the positives.

Your turn The milestone script

Write records.py: make a list of 3 job dicts, each with a name and a price. Loop over them and print each job's name with a 10% surcharge added to its price. Then use a list comprehension to build a list of just the names. This is your Session 3 milestone (a list of records, transformed), so try it before peeking.

Show reference solution 
jobs = [
    {"name": "Move", "price": 300},
    {"name": "Pack", "price": 120},
    {"name": "Storage", "price": 80},
]
for job in jobs:                 # step through each record
    name = job["name"]           # pull the fields out by key
    total = job["price"] * 1.1   # add a 10% surcharge
    print(f"{name}: ${total:.2f}")   # f-string + :.2f from Session 1 -> Move: $330.00

names = [job["name"] for job in jobs]   # comprehension: one field from each record
print(names)                     # ['Move', 'Pack', 'Storage']
