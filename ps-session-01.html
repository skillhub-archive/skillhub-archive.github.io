A. A terminal, a shell, and two PowerShells

A terminal is a window you type into. The program running inside it is the shell: it reads what you type, runs it, and prints the result. Each instruction you give it is a command. The shell shows a prompt, a short piece of text that means “ready, type a command”, you type after it and press Enter, and the result appears underneath.

PowerShell is a shell made by Microsoft, and also a language for writing scripts, which this track reaches in Level 3. There are two PowerShells, and telling them apart matters from today:

Name
Program
What it is
Windows PowerShell 5.1
powershell.exe
Built into every copy of Windows 10 and 11. Still supported, but it gets no new features. You will meet it at work.
PowerShell 7
pwsh
The current version: free, and it runs on Windows, macOS and Linux. This track teaches PowerShell 7.

The two are close cousins, so almost everything you learn works in both. Where 5.1 behaves differently, a box marked Windows PowerShell 5.1 says so. You will also see boxes marked In Bash. Bash is the standard shell on Linux. zsh, the default on a Mac, behaves the same as Bash for everything in this session; where it differs in a later one, the box says so. Those boxes show how the same job is done there, because the Linux shell is the natural next thing to learn after this.

On Windows, the friendliest terminal is Terminal, which comes with Windows 11. It can hold several shells, each in its own tab. Until you install PowerShell 7, it opens Windows PowerShell 5.1, and that is fine for the one install command below. winget is the program Windows 11 includes for installing other programs from the command line.

B. Which PowerShell am I in?

The two PowerShells look alike, so check rather than guess. Type this and press Enter:

PowerShell 7 · captured live
PS C:\Users\you> $PSVersionTable.PSVersion

Major  Minor  Patch  PreReleaseLabel BuildLabel
-----  -----  -----  --------------- ----------
7      6      5

The number under Major is the one that matters: 7 means PowerShell 7. The minor and patch numbers may be higher on your machine, because they grow with every update. You do not need to understand how this command works yet, only to type it and recognise what it says; you will use it often. For the curious: $ marks a variable, a named value PowerShell keeps; $PSVersionTable is one PowerShell fills in itself with facts about its own version; and .PSVersion reads one part of it. Session 5 teaches variables properly.

Windows PowerShell 5.1The same command in Windows PowerShell 5.1 printed this, on the same machine: 
PS C:\Users\you> $PSVersionTable.PSVersion

Major  Minor  Build  Revision
-----  -----  -----  --------
5      1      26100  9168
A 5 under Major means you are in the older version. Even the column names differ. Open a PowerShell 7 tab instead.

On Windows, choose the shell from Terminal’s tab menu. Select the ˅ arrow next to the + at the top of the window: the list shows every shell Terminal knows. On the Windows 11 machine this workbook was checked on, PowerShell 7 appears as PowerShell and the older one as Windows PowerShell. To make new tabs open PowerShell 7 every time, open the same menu, choose Settings, select Startup, set Default profile to the PowerShell 7 entry, and save. Then run the version check again in a new tab: that number, not the tab’s name, is the proof.

On macOS and Linux there is nothing to change: your terminal starts your usual shell, typing pwsh starts PowerShell 7 inside it, and typing exit takes you back.

C. Build the practice lab

Every session in this track practises on the same thing: the files of Fernhill Goods, a made-up online shop that sells kitchenware. You build them now, in your home folder, the folder your computer keeps for your own files (on Windows, C:\Users\ followed by your user name). The block below creates a folder there called ps-lab, with web server logs, the shop’s orders and support tickets as CSV files (a spreadsheet saved as plain text: one row per line, commas between the columns), and a messy folder of exports.

It is a set of PowerShell commands you paste rather than type. You are not expected to read it yet; by Level 3 you will be able to write one like it. Lines starting with # are comments: notes for people, which PowerShell ignores. The block sets every file’s contents and date exactly, so your lab matches this workbook to the byte. It deletes any folder called ps-lab in your home folder before it builds the new one, so if you already have one for something else, rename it first.

  1. In your terminal, check you are in PowerShell 7 (section B).
  2. Select the whole block with the button under it, and copy it with Ctrl+C (Cmd+C on a Mac).
  3. Paste it into the terminal with Ctrl+V (Cmd+V on a Mac). If Windows Terminal warns that the text contains more than one line and asks whether to paste it, choose to paste it: the block is meant to be many lines.
  4. If nothing starts running, press Enter. When it finishes, it moves you into the lab and lists what is there.
the lab setup block · paste into PowerShell 7
# Builds the Fernhill Goods practice lab in your home folder.
# Safe to paste again at any time: it deletes ps-lab and rebuilds it.
$lab = Join-Path $HOME 'ps-lab'
Set-Location $HOME   # step out first: a folder you are standing in cannot be deleted
if (Test-Path $lab) { Remove-Item $lab -Recurse -Force }
$enc = New-Object System.Text.UTF8Encoding($false)
function Add-LabFile($rel, $lines, $when) {
  $path = Join-Path $lab $rel
  $dir = Split-Path $path -Parent
  if (-not (Test-Path $dir)) { New-Item -ItemType Directory -Path $dir | Out-Null }
  $text = ''
  if ($lines.Count -gt 0) { $text = ($lines -join "`n") + "`n" }
  [System.IO.File]::WriteAllText($path, $text, $enc)
  (Get-Item $path).LastWriteTime = [datetime]$when
}

D. The shape of every command: Verb-Noun

PowerShell’s own commands are called cmdlets (say “command-lets”), and every one is named the same way: a verb, a hyphen, then a noun. The verb says what to do and the noun says what to do it to. Three you use today:

Verb
Cmdlet
Asks
Get
Get-Location
Which folder am I in?
Get
Get-ChildItem
What is inside this folder? Anything inside a folder is one of its child items.
Get
Get-Content
What does this file say?

The folder you are in right now is your current location, and a command that needs a folder uses it unless you name another. That is why Get-ChildItem on its own listed the lab:

where am I · captured live
PS C:\Users\you\ps-lab> Get-Location

Path
----
C:\Users\you\ps-lab

Parameters change what a command does. Each is written after the command’s name as a hyphen and a name, usually followed by a value, with spaces between them. -Path tells Get-ChildItem which folder to look in:

a parameter with a value · captured live
PS C:\Users\you\ps-lab> Get-ChildItem -Path logs

    Directory: C:\Users\you\ps-lab\logs

Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
d----            3/4/2026  8:00 AM                archive
-a---            3/3/2026 11:59 PM            147 app-2026-03-03.log
-a---            3/1/2026 11:59 PM            292 web-2026-03-01.log
-a---            3/2/2026 11:59 PM            193 web-2026-03-02.log
-a---            3/3/2026 11:59 PM            366 web-2026-03-03.log

Some parameters can be given without their name, because the command knows which value comes first: for Get-ChildItem that is the path, so Get-ChildItem logs does exactly the same as the command above. Section F shows how to find out which parameters work like that.

Other parameters take no value at all. These are switches: they are on just by being there. Four switches of Get-ChildItem you use today: -Name prints only the names; -File lists only files and -Directory only folders; and -Recurse looks inside every folder within the folder too, all the way down.

Each line of the shop’s web log is one visit to its website: when, how serious (INFO, WARN or ERROR), what was asked for, and the three-digit code that came back, where 200 and 201 mean it worked and anything from 400 up means it did not.

Three habits that save typing. Case does not matter in command and parameter names: get-childitem -name works, though the capitalised form is easier to read. Press Tab to finish a name: type Get-Chi and press Tab, and PowerShell completes it. On Windows, pressing Tab again shows the next possibility, if there is one. And a word in capitals in this workbook’s prose, like Get-Content FILE, is a stand-in for something you supply: you type a real file’s name, never the word FILE.

E. Moving around: paths

A path is the address of a file or folder: the folder names on the way to it, with a slash between each. There are two kinds. An absolute path starts at the very top, so it means the same thing wherever you are: C:\Users\you\ps-lab\logs on Windows, /Users/you/ps-lab/logs on a Mac. A relative path starts from your current location: from inside the lab, logs/archive means the archive folder inside logs, inside here.

Three short names save most of the typing:

Write
Means
Example from the lab
..
the folder above this one
from logs, .. is ps-lab; ../.. goes up two
~
your home folder
~/ps-lab is the lab, from anywhere
.
this folder
rarely needed today; it returns in Level 3

Set-Location moves you: give it a path and it makes that your current location. It prints nothing when it works; the prompt changes instead, so the prompt always tells you where you are:

moving down and back up · captured live
PS C:\Users\you\ps-lab> Set-Location logs
PS C:\Users\you\ps-lab\logs> Set-Location archive
PS C:\Users\you\ps-lab\logs\archive> Get-Content web-2026-02-28.log
2026-02-28 16:40:00 INFO  GET /products 200
2026-02-28 16:41:12 ERROR GET /cart 503 maintenance
PS C:\Users\you\ps-lab\logs\archive> Set-Location ../..
PS C:\Users\you\ps-lab>

A relative path is read from where you are when you type it, so the same command can work in one place and fail in another. From the lab itself there is no archive to move into:

the wrong starting point · captured live
PS C:\Users\you\ps-lab> Set-Location archive
Set-Location: Cannot find path 'C:\Users\you\ps-lab\archive' because it does not exist.

The error even prints the absolute path it tried, which tells you where it looked. Slashes: Windows writes paths with \, and PowerShell on Windows also accepts /, which is what macOS and Linux use. This workbook types / so every command works on all three; PowerShell still prints Windows paths with \. Capital letters: on Windows, readme.txt finds README.txt. Microsoft’s documentation says file systems on macOS and Linux are usually case-sensitive, and PowerShell follows the file system, so type every name exactly as it is printed and your commands work everywhere.

F. Finding commands you have never seen

Nobody remembers every command. What experienced people know is how to find one, and PowerShell has two cmdlets for exactly that. Get-Command finds commands by name. Because every name is Verb-Noun, you can search by either half. A * in a name is a wildcard, standing for any number of any characters, so *-Location means “every name that ends in -Location”. -Noun searches the noun half for you:

every command about locations · captured live
PS C:\Users\you\ps-lab> Get-Command -Noun Location

CommandType     Name                                               Version    Source
-----------     ----                                               -------    ------
Cmdlet          Get-Location                                       7.0.0.0    Microsoft.PowerShell.Management
Cmdlet          Pop-Location                                       7.0.0.0    Microsoft.PowerShell.Management
Cmdlet          Push-Location                                      7.0.0.0    Microsoft.PowerShell.Management
Cmdlet          Set-Location                                       7.0.0.0    Microsoft.PowerShell.Management

Read the Name column. Two of those are new. Push-Location moves you to a folder, like Set-Location, but first remembers where you were; Pop-Location then takes you back there. The other columns say where each command comes from, and their numbers differ between versions: 5.1 shows 3.1.0.0 where 7 shows 7.0.0.0. -Verb searches the other half in the same way, and a wildcard works in either: Get-Command -Noun *Item* finds every noun with Item in it. That one also lists commands from other programs installed on your computer, so its list varies from machine to machine.

Get-Help tells you how to use a command once you know its name. On a new install it shows a short version, and its most useful part is SYNTAX, which lists every parameter the command takes:

Get-Help Get-ChildItem, the start · captured live, long lines cut short here
PS C:\Users\you\ps-lab> Get-Help Get-ChildItem

NAME
    Get-ChildItem

SYNTAX
    Get-ChildItem [[-Path] <string[]>] [[-Filter] <string>] [-Include <string[]>]   cut short
    [-Depth <uint>] [-Force] [-Name]                                           cut short
                                      it goes on, then ALIASES and REMARKS

The syntax has its own small language, and these marks cover almost all of it:

In SYNTAX
Means
So you can type
[-Recurse]
square brackets: optional
leave it out, or add -Recurse. No angle brackets after it, so it is a switch.
<string>
angle brackets: the kind of value
a string is text; <string[]>, with [], means one or more of them, separated by commas
<int> <long> <uint>
kinds of whole number
a value such as 2; the names differ only in how big a number fits
[-Path] <string[]>
only the NAME is in brackets
the value is required, the name is optional: Get-Content README.txt
[[-Path] <string[]>]
the whole thing in brackets too
leave it out completely, as Get-ChildItem alone does
order
parameters whose name is optional take values in the order listed
for Get-ChildItem: first -Path, then -Filter

That last row explains a command you can now read. -Filter keeps only the names that match a pattern, wildcards included, so Get-ChildItem logs -Filter *.log lists the names in logs ending in .log. Because -Filter comes second in the syntax, Get-ChildItem logs *.log means the same thing: the first value is the path and the second is the filter.

Under SYNTAX, ALIASES lists the command’s short names, and REMARKS says this is only partial help. The full version, with a description of every parameter and worked examples, comes in two ways: Get-Help Get-ChildItem -Online opens it on Microsoft’s website, or Update-Help downloads all of it to your computer once. Neither is needed today.
