PowerShell & Automation // 20-Hour Sprint

PowerShell, stop clicking, start telling

Every job you do by clicking through folders, opening files and copying numbers out of them is a job a few lines of PowerShell can do for you, the same way every time. This sprint takes you from never having opened a terminal to writing tested scripts that run on a schedule, and shows the Linux shell’s way of doing each thing beside PowerShell’s. Ten two-hour sessions, five levels, a milestone at every step.

How this Sprint Works

Each session is about 1h45 of hands-on work in a real terminal plus a built-in 15-minute review. You practise on the files of a made-up online shop, which Session 1 builds on your own computer with one paste, so nothing you run can touch anything real. Every session also shows how the same job is done in Bash, the standard shell on Linux and close kin to zsh on a Mac, because that is the natural next step. The arc: talk to the shell, work with real data, write scripts, make them robust and scheduled, then package and test them.

The Five Levels

Sessions ship one at a time, so each can absorb what was learned building the last one. Work them in order, Session 1 through 10, since later sessions build on earlier ones and re-test them. Tick the box when you finish a session so this page tracks where you are. Nothing here needs an account or a paid tier: Session 1 installs PowerShell 7, Session 5 adds a free code editor, and Session 9 downloads a free testing module.

Using this Hub

Go in order. Every session assumes the one before it. Levels 3 through 5 build directly on the commands and the pipeline Level 1 sets up.

One terminal and one practice lab, all ten sessions. Session 1 installs PowerShell 7 and builds a folder of made-up shop files in your home folder. Every later session works on those files, and any session can rebuild them from scratch with one paste.

Windows, macOS or Linux. PowerShell 7 runs on all three. The sessions are written and checked on Windows, and wherever a step differs on macOS or Linux, the session says so. Windows PowerShell 5.1, the older version built into Windows, is flagged wherever it behaves differently.

Two hours is a guide, not a target. Finishing in ninety minutes is fine, and so is taking three hours.

Tick sessions as you finish them so the panel above stays honest, and export a copy if you switch machines.

Top 5 Resources

Four of these five are free. Each is here for a specific job, so use them where they help rather than reading them end to end.

01

PowerShell 101

Free · Microsoft Learn · Mike F. Robbins

A short, practical book republished free on Microsoft’s own documentation site, written for people who have only ever pointed and clicked. It covers the same ground as this track’s Levels 1 and 2. Its examples were written in Windows PowerShell 5.1, so where its output differs from yours, this track’s 5.1 notes explain why.

learn.microsoft.com · PowerShell 101
During: alongside Levels 1–2, for a second explanation of the same ideas.
02

Learn PowerShell in a Month of Lunches

Paid · 4th edition, 2022 · Plunk, Petty, Leonhardt · Manning

The standard beginner’s book, in short chapters meant to take an hour each. The fourth edition was updated by members of the PowerShell team for PowerShell 7 on Windows, Linux and macOS, which matches this track exactly.

manning.com · Month of Lunches
During: any level, when you want the longer version of a topic.
03

PowerShell reference: the about topics

Free · official

Microsoft’s reference pages on how the language itself works, one topic per page: aliases, the pipeline, wildcards, error handling, scripts and more. Dense and not a tutorial, which is exactly why it belongs here: once you know what a thing is called, this is where you learn all of it.

learn.microsoft.com · about topics
After: for precision on one feature, not for learning it the first time.
04

PowerShell Practice and Style Guide

Free · community, PoshCode

A community guide to writing PowerShell that other people can read and reuse: naming, layout, help, output and error handling. Guidelines rather than rules, written by people who maintain a lot of scripts.

poshcode.gitbook.io · Practice and Style
During: Levels 3–5, once you are writing scripts to keep.
05

Pester documentation

Free · official

Pester is the testing tool for PowerShell: you write small checks that prove your functions do what you meant, and run them before every change. Its own documentation starts with a quick start and is the reference for Level 5.

pester.dev · quick start
During: Level 5, when you write your first tests.
