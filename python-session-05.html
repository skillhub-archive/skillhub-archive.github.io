A. Opening a file the safe way: with

To touch a file you first open it. The built-in open(path, mode) function hands you back a file object you read from or write to. The catch: an open file holds a system resource, and you must close it when done or you risk lost data and locked files. The clunky manual way makes you remember that yourself:

# The manual way: YOU must remember to close it
f = open("notes.txt", "w")
f.write("hello")
f.close()                  # forget this line and data can be lost or the file stays locked

The fix is the with statement. A with block is a context manager: a wrapper that sets something up and then guarantees the matching teardown when the block ends. For a file, the teardown is closing it, automatically, even if your code crashes partway. This is the standard, idiomatic way to work with files, so use it every time:

# The clean way: with auto-closes the file for you, even if an error happens
with open("notes.txt", "w") as f:   # "as f" names the file object
    f.write("hello")                # write into the file; indented, so it runs while the file is open
# file is automatically closed right here, no f.close() needed

B. Reading: the whole file vs one line at a time

Opening with no mode (or "r") means read. Once open, you have two everyday choices. Call .read() to slurp the entire file into one string, simple, but it loads the whole thing into memory. Or iterate the file object in a for loop to walk it one line at a time, which scales to huge files. One wrinkle: each line you read still carries its trailing newline character (written \n, the invisible "start a new line" marker), so you usually call .strip() on it to shave off that newline and any stray spaces. The same is true of .read(): it hands back every character in the file, including the newline at the very end (most editors add one), so printing the whole string can leave a trailing blank line. That is a big reason the line-by-line approach below tends to read more cleanly.

greetings.txt contains
Hello
World
# Option 1: read the WHOLE file into a single string
with open("greetings.txt") as f:
    content = f.read()     # one big string, every newline included
print(content)             # the newlines become real line breaks -> Hello
                           World
                           # + a blank line here, because the file ends in a newline (most do)

# Option 2: iterate line by line, the cleaner read for most work
with open("greetings.txt") as f:
    for line in f:                 # the file hands you one line each loop
        print(line.strip())        # .strip() shaves the trailing newline off each -> Hello
                                   World

C. Writing: "w" overwrites, "a" appends

The mode you pass to open() decides what writing does, and mixing these two up is a classic way to lose data. "w" (write) opens the file empty: it erases anything already there before you write a single character. "a" (append) keeps the existing contents and adds your new text onto the end. Use .write() to put text in; unlike print, it does not add a newline for you, so end your lines with \n yourself when you want them separated.

# "w" starts fresh, wiping whatever was in the file first
with open("log.txt", "w") as f:
    f.write("first line\n")     # \n is the newline character; .write adds none on its own

# "a" keeps what is there and adds to the end
with open("log.txt", "a") as f:
    f.write("second line\n")
# log.txt now holds BOTH lines. Opening with "w" again would wipe it back to empty.

A light word on paths and folders. Rather than gluing strings like "data" + "\\" + "log.txt" (and guessing at slashes), the standard library's pathlib builds paths safely with a / operator that does the right thing on Windows and Mac alike:

from pathlib import Path         # Path is a class for filesystem paths
folder = Path("data")           # a folder named data
file_path = folder / "log.txt"  # join with / -> a full path object
print(file_path)                # on Windows prints -> data\log.txt

D. CSV: rows in, rows out

A CSV (comma-separated values) file is just a text file where each line is a row and commas separate the columns, exactly what a spreadsheet export looks like. Two string methods make this tick, and they are worth knowing on their own. .split(",") cuts a string into a list of pieces at every comma; ",".join(...) is its mirror image, gluing a list of strings back into one string with a comma between each item:

row = "Move,300"
parts = row.split(",")     # cut on every comma into a list -> ['Move', '300']
print(",".join(parts))     # glue the list back into one string -> Move,300

You could parse a whole file by hand this way, but quoted fields and other edge cases make hand-splitting fragile, so Python ships a csv module that does it correctly. Bring it in with import csv. It gives you two ways to read:

  • csv.reader(f) hands you each row as a list of strings: ["Move", "300"].
  • csv.DictReader(f) treats the first row as headers and hands you each later row as a dict keyed by those headers: {"name": "Move", "price": "300"}. Usually the friendlier choice, and it ties straight back to the dicts you built in Session 3.
jobs.csv contains
name,price
Move,300
Pack,120
Storage,80
import csv                              # the CSV module

# DictReader turns each data row into a dict keyed by the header row
with open("jobs.csv") as f:
    reader = csv.DictReader(f)
    jobs = list(reader)                # collect all rows into a list of dicts
# jobs[0] is {"name": "Move", "price": "300"}  (note: price came in as a STRING)

Writing goes the other way with csv.writer (you hand it lists) or csv.DictWriter (you hand it dicts). With DictWriter you declare the column names once as fieldnames, call .writeheader() to lay down the header row, then .writerows(...) for the data. One Windows detail: pass newline="" when opening a file for CSV writing, or you get a blank line between every row.

import csv

rows = [{"name": "Move", "total": 330}, {"name": "Pack", "total": 132}]
with open("out.csv", "w", newline="") as f:      # newline="" avoids double-spaced rows on Windows
    writer = csv.DictWriter(f, fieldnames=["name", "total"])
    writer.writeheader()               # writes the column-name row: name,total
    writer.writerows(rows)             # writes every data row

E. The string trap (read this twice), then your milestone

Here is the single biggest gotcha in real-world data work, and it is the same one input() sprang on you back in Session 1: everything you read from a text file or a CSV cell comes back as a string, even when it looks like a number. The characters 4 and 2 sitting in a cell arrive as the text "42", not the number 42. If you try to do math on them without converting first, Python does the wrong thing quietly instead of erroring:

price = "42"               # a value straight from a CSV cell: it is TEXT
tax = "8"
print(price + tax)         # BROKEN: + glues strings, so you get -> 428
print(int(price) + int(tax))   # FIXED: convert to numbers first -> 50

So the rule for any CSV number: run it through int() (whole numbers) or float() (decimals) before you calculate. Forget, and "10" + "20" becomes "1020" instead of 30. This one bug accounts for a huge share of "why is my total wrong?" moments, so make converting a reflex.

Your turn The milestone: read → transform → write

This is your Session 5 milestone, the whole point of the session. Starting from the same jobs.csv shown above (headers name,price, three rows), write a script that: (1) reads the rows with csv.DictReader; (2) uses a function total_with_tax(price, rate=0.1) (yes, the one you built in Session 4, now fed a string, so convert inside it) to compute each total; (3) keeps only the jobs whose total is over 100; and (4) writes those results to a new file jobs_with_tax.csv. Build it before peeking, this is exactly the kind of task that will replace manual spreadsheet work for you.

Show reference solution 
import csv

def total_with_tax(price, rate=0.1):
    """Return the price plus tax (price arrives as a string, so convert it)."""
    return float(price) * (1 + rate)   # float() turns the text into a number first

# 1. read the raw rows into a list of dicts
with open("jobs.csv") as f:
    jobs = list(csv.DictReader(f))

# 2 + 3. transform each row, keep only totals over 100
results = []
for job in jobs:
    total = total_with_tax(job["price"])
    if total > 100:
        results.append({"name": job["name"], "total": f"{total:.2f}"})  # :.2f = money to 2 places (Session 1)

# 4. write the survivors to a brand-new CSV
with open("jobs_with_tax.csv", "w", newline="") as f:
    writer = csv.DictWriter(f, fieldnames=["name", "total"])
    writer.writeheader()
    writer.writerows(results)

print(f"Wrote {len(results)} rows")   # with the sample data -> Wrote 2 rows
