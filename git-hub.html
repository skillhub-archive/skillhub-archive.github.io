How this Sprint Works

Each session is ~1h45 of hands-on work plus a built-in 15-minute review. Session 1 creates a practice repository that is safe to destroy, and every dangerous command gets run there first, never on anything you care about. The arc: understand what Git actually is, then branch and collaborate, then learn to undo anything, and finally ship a live project and recover it when it breaks.

The Five Levels

All ten sessions are built, so open any card. Work them in order, Session 1 through 10, since later sessions build on earlier ones and re-test them. Tick the box when you finish a session so this page tracks where you are. Commands are shown for both PowerShell and Bash, so the track works on any operating system.

Using this Hub

Go in order. Every session assumes the one before it. Level 4 in particular is much safer once Level 1 has explained what the three areas are.

Each session tells you which folder it starts in. Most build a small fresh practice repository of their own, so you are never blocked by what an earlier session left behind. Two carry straight on from the session before, Session 2 and Session 6, and in both cases the previous session ends by telling you to keep that folder. Anywhere you are not told to keep it, deleting a practice folder between sessions costs you nothing.

Two hours is a guide, not a target. Finishing in ninety minutes is fine, and so is taking three hours.

Tick sessions as you finish them so the panel above stays honest, and export a copy if you switch machines.

Top 5 Resources

Four of these five are free. Each is here for a specific job, so use them where they help rather than reading them end to end.

01

Pro Git

Free · the standard

Chacon and Straub's book, free online under a Creative Commons licence. Gentle enough for chapter 1, thorough enough that chapter 10 explains Git's internals properly.

git-scm.com/book
During: Ch.2–3 track Levels 1–2 almost exactly.
02

Learn Git Branching

Free

An interactive visualiser where you type real commands and watch the commit graph rearrange itself. Nothing makes branching and rebasing click faster, because you see the graph move instead of imagining it.

learngitbranching.js.org
During: Level 2, then again for rebase in Level 4.
03

Oh Shit, Git!?!

Free

Solves the reverse-lookup problem: you cannot search Git's own docs for how to fix a mistake unless you already know the name of the thing you need. Organised by the situation you are in. Swear-free mirror at dangitgit.com.

ohshitgit.com
During: Level 4, then keep it bookmarked forever.
04

Atlassian: Merging vs. Rebasing

Free

The clearest short explanation of the one Git decision that genuinely confuses everyone. Well diagrammed, and honest that both solve the same problem differently rather than one being correct.

atlassian.com/git/tutorials/merging-vs-rebasing
During: Session 4, then re-read before Session 8.
05

The official Git reference

Free · reference

The authoritative manual pages. Dense and not a teaching text, which is exactly why it belongs here: once you know what a command is called, this is where you learn every flag it takes.

git-scm.com/docs
After: for precision, not for learning a concept.

Where to next

You finished the whole track: you can build a repository from nothing, branch and merge and resolve conflicts on purpose, run a pull request cycle, undo and recover work four different ways, and take a live project through shipping, breaking and fixing. This is not another level to clear. It is the view from the top of the sprint, and two honest ways to keep climbing.

Try this next: what Git looks like underneath

Every one of the ten sessions used what Git calls its porcelain: the friendly commands built for people, commit, merge, switch, log. Underneath sits the plumbing, a second set of commands built for scripts, and with them a small, genuinely elegant data model: four object types, a handful of refs, and nothing else. Session 8 opened this door when it explained why editing a commit produces a different hash, and Session 10 leaned on it again when a hook compared one ref name against another.

Why it is the natural next topic rather than just trivia: it is the difference between typing at Git and scripting against it. Once you can ask a repository a question with rev-parse, cat-file and for-each-ref, you can automate the reporting and checking work that this track only ever did by hand.

Where to learn it: Pro Git, chapter 10 (Git Internals) is the canonical treatment and it is free. That is resource 01 above, which is why its blurb says chapter 10 explains the internals properly. Read it with a throwaway repository open beside you and run every command it shows.

Hands-on bonus: there is now an optional workbook for exactly this, a real workbook in the same six-part format as the ten sprint sessions but deliberately outside the graded ten, so opening it does not change your 10/10. It builds a small lab repository, then reads every object in it by hand with cat-file, ls-tree, rev-parse and for-each-ref, and finishes by scripting a question about a repository that you cannot answer by looking.

Get it certified

This sprint cannot hand you a credential. If you want one that proves what you learned, these two are genuine proctored exams rather than course-completion badges, and both were checked as current in August 2026. Read the honest caveat underneath them before you pay for either.

CERT · best match

Source Control Management with Git (SC102)

Paid · Linux Foundation SkillCred · $79

By far the closest match to what this track taught, and the only one of the two that certifies Git itself rather than a hosting platform. Its published domains line up almost session for session: repository management, branching, reconciling changes, inspecting commits, working with remotes, undoing changes, and temporary commits, which is stash. Online, proctored, performance-based or multiple-choice, 45 minutes, and the credential does not expire.

Closest to what you learned
training.linuxfoundation.org/skillcred/git
CERT · platform

GitHub Foundations

Paid · exam GH-900 · regional pricing

Certifies GitHub the platform, not Git, so treat the overlap honestly: one of its seven assessed areas is "Understand Git and GitHub basics" and the rest covers repositories, collaboration, GitHub Projects, security and administration, which this track never taught. Proctored through Pearson VUE, 100 minutes. The official page states pricing by country rather than one figure, so check it there rather than trusting a third-party number.

If your work is GitHub-centred
learn.microsoft.com · GitHub Foundations

The honest caveat: there is no certification from the Git project itself, and no single Git exam that every employer recognises. Git is a tool rather than a product with an exam body, so every credential you will find certifies either a vendor platform or a training provider assessment. The Linux Foundation SkillCred above is the nearest thing to a vendor-neutral Git credential. For a tooling and automation role, a repository somebody else can read and a history somebody else can follow usually says more than a badge does.
