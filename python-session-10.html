A. The whole pipeline in one script

This session has no new library to learn. Instead you connect the ones you already have into one flow, the flow behind almost every data tool: pull data from somewhere, reshape and clean it, write the answer out. Here is the exact chain you will build, and which session each link comes from:

  • An authenticated, paginated pull (Session 8) asks an API for your data one page at a time and collects it into a single list of dicts.
  • That list of dicts is precisely what response.json() hands back (Session 7) when an endpoint returns a list.
  • pd.DataFrame(list_of_dicts) turns that same shape straight into a table (Session 9), one row per dict.
  • You clean it, group it, and df.to_csv(...) writes the finished report to a file (Sessions 9 and 5).

Notice the thread that has run through the whole back half of the sprint: the data is rarely the type you think it is, so you convert or clean it before you use it. A CSV cell looked like a number but was text (Session 5). A JSON body looked like a dict but was text until you parsed it (Session 7). A blank cell was not zero but NaN, a float (Session 9). Every step of this pipeline has one of those moments, and handling it is most of the work.

Step one is your credential. In Session 8 you created a GitHub personal access token (Settings > Developer settings > Personal access tokens > Tokens classic > Generate; it starts with ghp_) and stored it in an environment variable so it never sits in your code. Read it back with os.getenv and build the bearer header you will send on every request:

import os

token = os.getenv("GITHUB_TOKEN")                 # read the token from the environment, never hardcode it
headers = {"Authorization": f"Bearer {token}"}    # the bearer header, sent on every request (Session 8)

B. The authenticated, paginated pull

The first real step is fetch, and this is Session 8 almost verbatim, so it should feel familiar. You send your headers on a GET to the repos endpoint, and because an account can have more repos than fit in one response, you page: ask for page 1, then page 2, and so on, adding each page onto one list with .extend, until a page comes back with fewer items than you asked for, which means there is no more data (the Session 8 stop condition). Wrap the whole thing in try/except requests.RequestException (Sessions 6 and 8) so a network problem fails with a clear message instead of a raw traceback, and check for a 401 (Session 8) so a bad token tells you to fix your token. Notice this is already written as a function, one named job, we will make that a habit in Concept E:

import requests, os

def fetch_repos(headers):
    url = "https://api.github.com/user/repos"   # this endpoint requires a token
    repos = []
    page = 1
    try:
        while True:
            resp = requests.get(url, headers=headers, params={"per_page": 100, "page": page})
            if resp.status_code == 401:
                print("401: check your token.")
                return []
            resp.raise_for_status()          # any other bad status raises, caught below
            batch = resp.json()              # a list of repo dicts for this page
            repos.extend(batch)              # add this page onto the running list
            if len(batch) < 100:             # a page shorter than 100 means we are done
                break
            page += 1
    except requests.RequestException as e:
        print("Network error:", e)
        return []
    return repos

Here is the shape of what comes back, verified against the public equivalent of this endpoint. Each page is a list of repo dicts, and a repo dict has dozens of fields (most trimmed here):

C. Reshape and clean with pandas

Now hand that list of dicts to pandas. Because it is a list of dicts, pd.DataFrame(repos) turns it straight into a table (Session 9), one row per repo and one column per key. A repo object has dozens of fields you do not need, so select just the columns you care about with the double-bracket list form, df[["name", "language", "stargazers_count", "private"]] (Session 9). Then clean: some repos have no detected language, which comes in as NaN, so drop those rows with dropna (or fill them with fillna("Unknown") if you would rather keep them). This is the same clean-before-you-use-it habit as the rest of the pipeline:

import pandas as pd

def to_dataframe(repos):
    df = pd.DataFrame(repos)                                      # list of dicts -> table
    df = df[["name", "language", "stargazers_count", "private"]]  # keep only the columns the report needs
    df = df.dropna()                                              # drop repos with no language (a NaN)
    return df

D. Group, summarize, and write the report

With a clean table, the summary is one line (Session 9): group by language and total the stars. groupby("language")["stargazers_count"].sum() gives a total per language; reset_index() flattens it back into a plain two-column table; and to_csv("summary.csv", index=False) writes the report without pandas automatic row numbers. That file is your deliverable, it went from a live API to a finished report:

def summarize(df):
    summary = df.groupby("language")["stargazers_count"].sum().reset_index()   # total stars per language, flat table
    summary.to_csv("summary.csv", index=False)   # write the report, no extra 0,1,2 column
    return summary

E. Organizing the tool: functions and the main guard

You could write all of this as one long script, top to bottom: read the token, loop the pages, build the DataFrame, clean, group, write, all in a single flat file. It runs. But it is hard to test one piece without running the whole thing, hard to reuse the fetch without also triggering the report, and hard to read. Here is the tempting one-blob version (shortened):

headers = {"Authorization": f"Bearer {token}"}
repos = []
page = 1
while True:
    ...                                        # the whole pagination loop, inline
df = pd.DataFrame(repos)
df = df[["name", "language", "stargazers_count", "private"]].dropna()
summary = df.groupby("language")["stargazers_count"].sum().reset_index()
summary.to_csv("summary.csv", index=False)
print(summary)

The organized version is the same logic split into named functions, each doing one job (Session 4), with a main() that calls them in order. This is the Session 4 lesson (functions take inputs and return values) applied to a whole tool, the return value of each step is the input to the next:

def main():
    token = os.getenv("GITHUB_TOKEN")
    if not token:
        print("Set GITHUB_TOKEN first (see Session 8).")
        return
    headers = {"Authorization": f"Bearer {token}"}
    repos = fetch_repos(headers)               # step 1: pull (returns a list of dicts)
    print(f"Pulled {len(repos)} repos.")
    df = to_dataframe(repos)                   # step 2: reshape and clean (returns a DataFrame)
    summary = summarize(df)                    # step 3: group and write (returns the summary)
    print(summary)

if __name__ == "__main__":
    main()

That last block is new, and it sits at the bottom of nearly every Python tool, so it is worth understanding rather than copying. __name__ is a built-in variable that Python sets automatically for every file. When you run a file directly (python capstone.py), Python sets that file's __name__ to the string "__main__". But when another file imports your file to reuse its functions, Python sets __name__ to the module's name instead (for example "capstone"). So the line if __name__ == "__main__": reads as: run this block only when the file is being run directly, not when it is being imported. That means running the tool does the work, while importing it just loads fetch_repos and the others for reuse elsewhere, without firing off a network pull as a side effect. It is the standard way to give a file both a "run me" behavior and a "borrow my functions" behavior.

Two light finishing touches make a tool something you (or a teammate) can re-run later. First, capture the exact packages it needs: pip freeze > requirements.txt (Session 6) writes requests, pandas, and their versions to a file, so anyone can pip install -r requirements.txt and get the same setup. Second, add a short README, a plain text file that says what the tool does, how to set the token, and how to run it. That is the difference between a script on your machine and a tool someone else can pick up.

import pandas as pd

def fetch_repos(headers):
    url = "https://api.github.com/user/repos"
    repos = []
    page = 1
    try:
        while True:
            resp = requests.get(url, headers=headers, params={"per_page": 100, "page": page})

                break
            page += 1

        return []

def to_dataframe(repos):
    df = pd.DataFrame(repos)
    df = df[["name", "language", "stargazers_count", "private"]]
    return df.dropna()

def summarize(df):
    summary = df.groupby("language")["stargazers_count"].sum().reset_index()
