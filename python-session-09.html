A. What pandas is, and its two core objects

In Session 5 you read a CSV with csv.DictReader, which handed you a list of dicts, one dict per row, and then you wrote a for loop to total or filter it by hand. pandas is a data library that skips the loop: it loads the whole table into one object and lets you clean, filter, and summarize entire columns in a single line. It is the tool professionals reach for the moment data gets bigger than a handful of rows, and it is what sits underneath most data dashboards and report builders.

pandas gives you two objects, and every single thing today is built from them:

  • A Series is a single column of data with a label, one-dimensional, like a list where every value also has a position (an index) attached. A single column pulled out of a table is a Series.
  • A DataFrame is a whole table: rows and columns, two-dimensional. You can think of it as many Series lined up side by side, all sharing the same row index. This is the object you will spend today working with.

Because pandas is a third-party package (not part of Python, the same as requests was in Session 6), you install it once with pip, then import it. The community always imports it under the short alias pd using the as keyword, which renames the import so you can type pd everywhere instead of pandas. You will see import pandas as pd at the top of essentially every pandas script in the world, so use it too. You build a Series directly from a list with pd.Series([...]), and once you have one you can operate on the whole thing at once, for example add every value with .sum():

import pandas as pd    # "as pd" gives the pandas library the short nickname pd for the rest of the file

s = pd.Series([10, 20, 30])   # build a Series straight from a list of values
print(s.sum())                # a Series can add itself up in one call -> 60

B. Getting data in, and looking at it

There are two everyday ways to get a DataFrame. The first is to read a file. pd.read_csv("jobs.csv") reads a whole CSV into a DataFrame in one line, the pandas counterpart to Session 5's csv.DictReader plus its loop, and it figures out the columns and the types for you. The second is to build one from data you already have in code: pd.DataFrame(...) takes either a dict of columns, {"name": [...], "amount": [...]}, or a list of dicts, [{"name": "A", "amount": 100}, ...], which is exactly the shape Session 7's response.json() handed back. Same table, two entry points:

import pandas as pd

df = pd.read_csv("jobs.csv")                          # read a CSV file into a DataFrame
df = pd.DataFrame({"name": ["A", "B"], "amount": [100, 200]})   # or build one from a dict of columns

Once you have a DataFrame, four quick tools tell you what you are holding before you do anything with it:

  • df.head() shows the first few rows (five by default), so you can eyeball the data without printing thousands of lines.
  • df.shape is the size as a tuple (rows, columns), for example (5, 4) means five rows and four columns. len(df) (the same len from Session 3) gives just the row count.
  • df.columns lists the column names.
  • df["amount"].dtype is the dtype, the data type pandas inferred for that column (for example a whole-number column reads in as int64, a decimal column as float64). This matters a lot in Concept D.

C. Selecting columns and filtering rows

Grabbing a column uses the same square brackets as a dict key from Session 3. Watch the single-versus-list distinction, because it changes what you get back:

  • df["amount"], one name in the brackets, returns that single column as a Series.
  • df[["name", "amount"]], a list of names (note the double brackets), returns a smaller DataFrame with just those columns.

Filtering rows is where pandas feels different from a loop. You build a boolean mask, a Series of True/False, one per row, by writing a comparison against a whole column at once, and then you index the DataFrame with it to keep only the True rows:

big = df[df["amount"] > 100]     # df["amount"] > 100 is True/False per row; keep only the True rows

Here is the gotcha that trips up everyone at first. To combine two conditions you do not use Python's and / or from Session 2. Those work on single True/False values, but a mask is a whole column of them, so pandas needs the elementwise operators & (and) and | (or), which compare the columns position by position. Each condition must be wrapped in its own parentheses, because & binds more tightly than the comparisons do:

hit = df[(df["amount"] > 100) & (df["status"] == "won")]   # rows where BOTH are true; note the () around each side

Writing plain and there raises an error, so reach for & and | whenever a mask has more than one condition. There is also df.loc[...], the label-based selector, for picking rows and columns by their labels at the same time (for example df.loc[df["amount"] > 100, "name"] gives the names of the matching rows); you will see .loc often in pandas code, so it helps to recognize it.

D. Cleaning messy data (the heart of the milestone)

Real data has holes, and this is the concept that makes or breaks a report. When pandas reads a CSV and a cell is empty, it does not store an empty string "" or a zero. It stores NaN, which stands for "not a number" and is a special float value meaning "missing." That has a consequence people hit constantly: a column of otherwise-whole numbers that has even one blank cell is read in as float64 (decimals), not int64, because NaN itself is a float. So the values come back as 1200.0, 800.0, NaN, and so on.

Two tools deal with the missing values:

  • df.dropna() returns the DataFrame with every row that contains a missing value removed. Use it when a row with a hole is not worth keeping.
  • df.fillna(value) returns the DataFrame with every missing value replaced by value, for example df.fillna(0). Use it when a sensible default beats dropping the row.

Once the holes are handled you often want to fix the type, and there are two ways. df["amount"].astype(int) converts a column to a given type (int, float, str), and pd.to_numeric(df["amount"]) turns a text column into numbers. This is Session 5's "a CSV cell is text, convert it before you do math" lesson, now applied to a whole column at once.

Here is the trap, and the reason order matters. If you try to convert a column that still has a NaN in it straight to int, pandas cannot do it (there is no integer for "missing"), and it raises an error, pandas calls it an IntCastingNaNError:

# amount has a blank, so it read in as float64 with a NaN in it
df["amount"].astype(int)     # ERROR: cannot convert NaN to an integer

So the fix is an order you will use every time: handle the missing values first with dropna or fillna, and only then convert the now-clean column with astype. Clean, then convert.

df = df.dropna()                          # 1. remove the rows with a missing value
df["amount"] = df["amount"].astype(int)   # 2. now the column is safe to turn into whole numbers

E. Group, summarize, export, and the loop-versus-pandas payoff

The single most useful thing pandas does for reporting is group and aggregate. df.groupby("salesperson")["amount"].sum() reads as: split the rows into groups by salesperson, then within each group add up amount. This is the split-apply-combine idea: split into groups, apply a calculation to each, combine the answers into one result. Swap .sum() for .mean() (the average, which always comes back as a float, so a clean 4 prints as 4.0) or .count() (how many non-missing values are in each group) to summarize differently. The result is a Series labeled by each group, so you can read one group back by its label, totals["Sam"], just like a dict key.

Now the payoff, and why this whole level exists. Here is Session 5's manual way to total amounts per salesperson, next to the pandas way:

# THE LOOP WAY (Session 5 style): you write every step yourself
totals = {}                                  # an empty dict to accumulate into
for row in rows:                             # walk the list of dicts one row at a time
    person = row["salesperson"]              # the group key for this row
    totals[person] = totals.get(person, 0) + int(row["amount"])   # running total per person
# THE VECTORIZED WAY (pandas): one line, no loop
totals = df.groupby("salesperson")["amount"].sum()   # same per-person totals, computed on the whole column at once

The pandas version is called vectorized: pandas applies the operation to the whole column at once, in fast internal code, instead of you writing a Python loop over the rows. Less code, fewer bugs, and much faster on big data. That single idea, operate on the column not the row, is the reason Level 5 is worth your time.

Finally, write your answer out. df.to_csv("summary.csv") saves a DataFrame back to a CSV file. By default it also writes pandas' automatic row numbers (0, 1, 2, ...) as an extra first column, which you usually do not want in a report, so pass index=False to leave them out. One wrinkle: a grouped result is a Series labeled by the group, so to get a clean flat table first call .reset_index(), which turns those group labels back into a normal column. Then export:

summary = df.groupby("salesperson")["amount"].sum().reset_index()   # flat table: a salesperson column + an amount column
summary.to_csv("summary.csv", index=False)    # write it out, without the extra 0,1,2 index column
