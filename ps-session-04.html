Session 1 called a CSV file a spreadsheet saved as plain text: one row per line, commas between the columns, and a first line, the header, that names the columns. Read with Get-Content, it is just that, lines of text:

B. Text that looks like a number

A Total of 34.00 is text, the same as '34.00' in single quotes, and Session 2 showed what that does to a sort: '96' lands after '366'. It does more than that. When PowerShell combines two values, the value on the left decides how. With text on the left, + joins text, and a comparison compares text, letter by letter:

text on the left · captured live
PS C:\Users\you\ps-lab> '34.00' + 1
34.001
PS C:\Users\you\ps-lab> '9' -gt 30
True

34.001 is 34.00 with a 1 stuck on the end, and '9' is “greater” than 30 because the character 9 comes after the character 3. And when one text runs out first, as '1' against '10', the shorter one is smaller, as in a dictionary. To get a number, convert the text by putting a type name in square brackets in front of it. [int] makes a whole number (int is short for integer), and [double] makes a number that can have a decimal point, which is what you want for a price. (Double is .NET’s name for that kind of number.)

converted first · captured live
PS C:\Users\you\ps-lab> [double]'34.00' + 1
35
PS C:\Users\you\ps-lab> [int]'9' -gt 30
False
PS C:\Users\you\ps-lab> [int]'22.50'
22
PS C:\Users\you\ps-lab> [int]'23.50'
24

The last two are the catch with [int]: it rounds to the nearest whole number, and an exact half goes to whichever neighbour is even, so 22.50 becomes 22 but 23.50 becomes 24. Either way the price is changed: use [double] for prices and [int] for counts. Notice too that a number prints without its trailing zeros: 35, not 35.00. Here is the trap in a real file. exports/inventory-dump.csv has a Stock column, from 0 to 36. Asked for items with more than 30 in stock, Where-Object compares Stock as text, because Stock is on the left:

more than 30 in stock? · captured live

---      ----   -----
SKU-0004 Item 4 4
SKU-0005 Item 5 5
SKU-0006 Item 6 6

4, 5 and 6 all passed. To convert inside a filter, use Session 2’s script block form, where $_ is each row and the dot reads its Stock: { [int]$_.Stock -gt 30 }. Converted, the first three are the right ones:

converted, then compared · captured live

SKU-0033 Item 33 33

Sort-Object takes a script block too, and sorts by whatever the block gives back for each object. Without one, a sort on Stock is a text sort, and the “biggest” stock is 9:

the biggest stock, sorted as text and as a number · captured live
PS C:\Users\you\ps-lab> Import-Csv exports/inventory-dump.csv | Sort-Object Stock -Descending |
  Select-Object -First 1 -ExpandProperty Stock                                one line, wrapped here

PS C:\Users\you\ps-lab> Import-Csv exports/inventory-dump.csv |
  Sort-Object { [int]$_.Stock } -Descending |                               one line, wrapped here
  Select-Object -First 1 -ExpandProperty Stock
36

The rule for today: a column from a CSV is text; convert it with [int] or [double] before you compare it, sort it or do arithmetic with it.

C. Counting and totalling: Measure-Object

Measure-Object counts what comes down the pipe. Name a column after it and add any of the switches -Sum, -Average, -Maximum and -Minimum, and it also works out the total, the average (the mean), the largest and the smallest value in that column:

count the rows, then measure a column · captured live
PS C:\Users\you\ps-lab> Import-Csv data/orders.csv | Measure-Object

Count             : 8
Average           : 
Sum               : 
Maximum           : 
Minimum           : 
StandardDeviation : 
Property          : 

PS C:\Users\you\ps-lab> Import-Csv data/orders.csv |                        one line, wrapped here
  Measure-Object Total -Sum -Average -Maximum -Minimum

Count             : 8
Average           : 43.1875
Sum               : 345.5
Maximum           : 82
Minimum           : 22.5
StandardDeviation : 
Property          : Total

It prints one object, as a list: Count is always filled in, the rest only when you ask, and Property names the column it measured. (StandardDeviation is a measure of spread you will not need here.) Two things to notice. Measure-Object converts the text to numbers for you, so no [double] is needed. And the results are numbers, so they print without trailing zeros: 345.5, 82. For just the number, so you can use it or save it, pick the property with -ExpandProperty, and to measure only some rows, filter first:

just the number, of all orders and of the shipped ones · captured live
PS C:\Users\you\ps-lab> Import-Csv data/orders.csv | Measure-Object Total -Sum |
  Select-Object -ExpandProperty Sum                                           one line, wrapped here

PS C:\Users\you\ps-lab> Import-Csv data/orders.csv | Where-Object Status -eq 'shipped' |
  Measure-Object Total -Sum | Select-Object -ExpandProperty Sum               one line, wrapped here
200.5

Two ways a measure goes wrong. A column that is not a number cannot be totalled: Measure-Object prints an error for every row that is not numeric, then a result with no Sum. A column name that is misspelt is quieter: PowerShell 7 prints nothing at all, which looks like a total of nothing.

D. Counting by group: Group-Object

Measure-Object counts everything it is given. Group-Object sorts what it is given into groups, one for each different value of the column you name, and counts each group:

tickets by state · captured live
PS C:\Users\you\ps-lab> Import-Csv data/tickets.csv | Group-Object State

Count Name                      Group
----- ----                      -----
    2 closed                    {@{TicketId=T-101; Opened=2026-03-01;   one line, wrapped here
Customer=Dara Singh; Topic=refund; Priority=high…
    3 open                      {@{TicketId=T-103; Opened=2026-03-03;   one line, wrapped here
Customer=Gus Lind; Topic=payment; Priority=high;…

Each group is an object with three properties: Count, how many rows it holds; Name, the value they share; and Group, the rows themselves, which PowerShell squeezes into one column and cuts off with … at the edge of your window. (A group has a fourth property, Values, which repeats the Name as a list; you can ignore it.) Usually you want only the first two, so pick them, the way the Hub’s first page does:

just the counts · captured live
PS C:\Users\you\ps-lab> Import-Csv data/tickets.csv | Group-Object State | Select-Object Count, Name

Count Name
----- ----
    2 closed
    3 open

Always sort the groups yourself. PowerShell 7 hands the groups on sorted by Name; Windows PowerShell 5.1 hands them on in the order it first met each value, which for the orders’ Status is shipped, refunded, pending. The same command gives a different report in each. Sorting with Session 2’s tie-breaker settles it, biggest group first and the Name breaking a tie, the same way in both:

E. Calculated properties: a column of your own

Select-Object can do more than pick columns: it can add one that you work out from the others. You describe the new column with a small recipe in this exact shape, @{ Name = 'TITLE'; Expression = { CODE } }, where TITLE and CODE in capitals are placeholders: you type the new column’s title in place of TITLE, and in place of CODE the PowerShell that works out its value.

Part
What it is
Example
@{ }
a hashtable: a little list of name = value pairs, separated by ;
@{ Name = 'Each'; Expression = { [double]$_.Total / $_.Qty } }
Name = 'TITLE'
the new column’s title, in single quotes
Name = 'Each'
Expression = { CODE }
a script block, run once for each object, with $_ as that object; what it gives back is the column’s value (/ means divide)
Expression = { [double]$_.Total / $_.Qty }

The whole recipe goes in Select-Object’s list of columns, like any other column name, and the result is called a calculated property. Here is the price of one item in each order, the Total divided by the Qty:

a column worked out from two others · captured live
PS C:\Users\you\ps-lab> Import-Csv data/orders.csv |                        one line, wrapped here

F. Writing a CSV: Export-Csv

Everything so far has printed on your screen. Export-Csv writes objects to a CSV file instead, one row per object, with a header made from their property names, so other people can open your result in a spreadsheet program such as Excel (the end of this section shows the one switch Excel needs). Like > and Copy-Item in Session 3, it replaces a file that is already there, without asking:

tickets by state, saved and read back · captured live
PS C:\Users\you\ps-lab> Import-Csv data/tickets.csv | Group-Object State |
  Select-Object Name, Count | Export-Csv out/by-state.csv                   one line, wrapped here
PS C:\Users\you\ps-lab> Get-Content out/by-state.csv
"Name","Count"
"closed","2"
"open","3"
PS C:\Users\you\ps-lab> Import-Csv out/by-state.csv

Name   Count
----   -----
closed 2
open   3

Read as text, every value is in double quotes. That is allowed in a CSV, and it keeps a value with a comma inside it in one piece; Import-Csv drops the quotes when it reads the file back. Read back with Import-Csv, the file is objects again, and Count is text again, lined up on the left.

Pick the columns before you export. Export-Csv writes every property, and a group’s Group property holds a whole list of rows, which a single CSV value cannot hold. Exported as they come, the groups are written as the names of the kinds of object that held them:

G. Writing JSON: ConvertTo-Json

CSV suits people with spreadsheets. Programs, and web services in particular, usually want JSON, a text format for data: curly braces { } hold one object, square brackets [ ] hold a list, and inside an object each property is written "name": value, with commas between them. ConvertTo-Json turns objects into JSON text:

two tickets, two columns, as JSON · captured live
PS C:\Users\you\ps-lab> Import-Csv data/tickets.csv |                       one line, wrapped here

    "TicketId": "T-101",
    "State": "closed"
  },
  {
    "TicketId": "T-102",
    "State": "closed"
  }
